1. Introducción a los Sistemas Operativos

1.1 Sistema Operativo en sentido amplio y en sentido estricto

El término "sistema operativo" puede entenderse de dos formas principales, dependiendo del nivel de detalle y del contexto en que se utilice.

1.1.1 Definición amplia y habitual

En su concepción más general, un sistema operativo incluye no solo el núcleo (kernel), sino también un conjunto más amplio de herramientas, utilidades y aplicaciones que permiten a los usuarios interactuar de manera efectiva con el hardware y los recursos del sistema. Esto abarca componentes como administradores de archivos, intérpretes de comandos (shells), sistemas de archivos, bibliotecas estándar, configuradores como paneles de control, y utilidades adicionales como terminales, editores de texto y otros programas que forman parte del entorno del sistema operativo. En este sentido, el sistema operativo es visto como un conjunto de aplicaciones accesibles al usuario, que le proporcionan una experiencia completa para la interacción con su equipo.

1.1.2 Definición técnica y estricta

Desde un enfoque más técnico, el término "sistema operativo" se refiere exclusivamente al núcleo (kernel), que es el componente más fundamental y esencial del software del sistema. Este núcleo opera de manera invisible para el usuario, ya que no es algo con lo que se interactúe directamente, sino que es el intermediario entre el hardware y las aplicaciones o procesos. El núcleo se encarga de tareas críticas como la gestión de la memoria, la asignación de tiempo de procesador, la comunicación entre procesos y el acceso a los dispositivos de hardware. Por tanto, el usuario no lo percibe directamente, pero su correcto funcionamiento es vital para que las aplicaciones puedan ejecutarse y brindar los servicios que el usuario utiliza.

En el resto de estos apuntes, el término "sistema operativo" hace referencia a la definición más técnica, es decir, al núcleo o kernel. Cuando sea necesario referirse al concepto más amplio, se indicará de manera explícita para evitar confusiones.

1.2 Roles y funciones del Sistema Operativo

El sistema operativo cumple dos roles esenciales que están estrechamente relacionados con sus funciones principales.

1.2.1 Administrador de Recursos

El sistema operativo actúa como un referee o árbitro entre las aplicaciones (o procesos) que compiten por los recursos del sistema. Esto es fundamental para garantizar que los recursos, como la CPU, la memoria y los dispositivos de entrada/salida, sean gestionados de manera eficiente y sin conflictos. Por ejemplo, cuando dos procesos necesitan utilizar la impresora, el sistema operativo se encarga de decidir cuál tendrá acceso primero, informando al segundo proceso que debe esperar a que la impresora se desocupe. De manera similar, si un proceso solicita más memoria RAM, el sistema operativo verifica qué direcciones de memoria están disponibles, asigna la memoria solicitada, y registra esa asignación para poder reutilizarla posteriormente cuando sea necesario. Esta capacidad de gestionar y coordinar los recursos asegura que múltiples aplicaciones puedan ejecutarse simultáneamente sin interferencias.

1.2.2 Máquina Extendida

Más allá de administrar recursos, el sistema operativo proporciona una capa de abstracción entre el hardware y los procesos, simplificando las interacciones y ofreciendo una interfaz uniforme. Esta abstracción permite que las aplicaciones realicen solicitudes de alto nivel al sistema operativo, en lugar de lidiar con la complejidad de las operaciones de bajo nivel del hardware. Por ejemplo, cuando un proceso necesita almacenar datos en un disco, no tiene que preocuparse por controlar qué sectores están ocupados y cuáles disponibles, o cómo comunicarse directamente con la controladora del disco. Sin el sistema operativo, cada programador tendría que implementar esta funcionalidad compleja en sus aplicaciones.

Gracias al sistema operativo, las aplicaciones pueden hacer solicitudes abstractas como "guardar este texto en tal archivo", dejando que el sistema operativo se encargue de traducir esta solicitud a las operaciones de bajo nivel necesarias para comunicarse con el hardware, como dividir los datos en bloques y escribirlos en sectores específicos del disco. Este concepto de "máquina extendida" es clave, ya que proporciona una interfaz más sencilla y práctica para los desarrolladores y usuarios.

Es importante destacar que conceptos como el de "archivo" no existen en el hardware; son abstracciones creadas por el sistema operativo para facilitar el manejo de los datos. En lugar de que las aplicaciones trabajen directamente con bloques o sectores, el sistema operativo permite que interactúen con archivos y carpetas, brindando un modelo más intuitivo y eficiente para los procesos.

En resumen, estos roles explican por qué es indispensable que una PC tenga un sistema operativo: por un lado, necesitamos un gestor que arbitre las solicitudes de recursos entre procesos y, por otro, un sistema que simplifique las interacciones con el hardware, proporcionando una interfaz abstracta y uniforme que facilite tanto el desarrollo como el uso de aplicaciones.

Dentro de este marco, el núcleo del sistema operativo desempeña las siguientes funciones específicas:

FunciónDescripción
Gestión de ProcesosSupervisa la creación, suspensión y finalización de procesos, garantizando su comunicación y sincronización. Actúa como mediador entre los procesos y los recursos disponibles.
Gestión de MemoriaControla la asignación y liberación de memoria, optimizando el uso de la RAM y proporcionando memoria virtual para expandir las capacidades del sistema.

1.3 Espacios del Kernel y de Usuario

Una forma de distinguir qué procesos forman parte del sistema operativo es identificar dónde se ejecutan y cómo interactúan con los recursos del sistema. Esta diferenciación está estrechamente vinculada con los modos de ejecución del procesador, que son el modo kernel y el modo usuario:

  • Modo Kernel: En este modo, las instrucciones en código máquina tienen acceso directo tanto al hardware como a toda la memoria RAM. Esto significa que las operaciones críticas, como gestionar dispositivos o asignar memoria, pueden llevarse a cabo sin restricciones. El espacio del kernel es donde se ejecutan los procesos que forman parte del sistema operativo, como el núcleo (kernel) y los controladores esenciales. Este espacio es exclusivo y está reservado para tareas que requieren control total sobre el sistema.
  • Modo Usuario: En este modo, las instrucciones del procesador no tienen acceso directo al hardware ni a la memoria del sistema, lo que protege la estabilidad y seguridad del sistema. Los procesos que operan en el espacio de usuario son considerados "normales" y deben realizar solicitudes al sistema operativo, conocidas como llamadas al sistema, para ejecutar operaciones privilegiadas como leer un archivo, asignar memoria o enviar datos a un dispositivo.

En este sentido, otro modo de definir un sistema operativo, además de por sus funciones, es como aquel software que se ejecuta en el espacio del kernel. Esto incluye el núcleo y otros componentes esenciales que interactúan directamente con el hardware para gestionar recursos y garantizar el funcionamiento correcto del sistema.

En resumen, los espacios del kernel y de usuario y sus respectivos modos de ejecución del procesador son fundamentales para entender cómo el sistema operativo controla el acceso al hardware y mantiene la seguridad del sistema. En el modo kernel, las instrucciones tienen control total sobre los recursos, mientras que en el modo usuario, los procesos están restringidos y dependen del sistema operativo para realizar operaciones más complejas. Esta arquitectura protege al sistema de errores y fallos potenciales, permitiendo un entorno controlado y seguro para las aplicaciones.

1.4 Tipos de Sistemas Operativos y relación con los modos de operación

Los sistemas operativos pueden clasificarse según cómo distribuyen sus componentes entre el espacio del kernel y el espacio de usuario, lo que influye directamente en su diseño y funcionamiento:

1.4.1 Monolíticos

El núcleo incluye todas las funciones esenciales y muchas no esenciales del sistema operativo. Todo el sistema operativo opera en el espacio del kernel, lo que proporciona alta eficiencia pero menos modularidad.

Ejemplo: Linux.

1.4.2 Microkernels

Solo las funciones más básicas (gestión de procesos, memoria y comunicación) residen en el espacio del kernel. Las demás funciones operan en el espacio de usuario, lo que mejora la modularidad y la seguridad a costa de un rendimiento ligeramente menor.

Ejemplo: Minix, QNX.

1.4.3 Híbridos

Combinan características de núcleos monolíticos y microkernels. Mantienen funciones críticas en el espacio del kernel, pero trasladan algunas funciones adicionales al espacio de usuario para lograr un balance entre eficiencia y modularidad.

Ejemplo: Windows NT, macOS.

Al observar cómo los procesos y funciones se distribuyen entre el espacio del kernel y el espacio de usuario, se obtiene una visión clara de las diferencias entre los diseños de sistemas operativos y su impacto en la seguridad, modularidad y eficiencia.

2. Comunicación entre el sistema operativo, los procesos, el hardware y el procesador

2.1 Las interrupciones

Las interrupciones son mecanismos fundamentales que permiten la comunicación entre el hardware, el procesador y el sistema operativo. Son eventos que cambian el flujo normal de ejecución de un programa, permitiendo al sistema responder a situaciones específicas de manera eficiente. Estas interrupciones operan bajo el control de dos modos del procesador: modo kernel y modo usuario.

El modo kernel permite la ejecución de instrucciones privilegiadas del sistema operativo, mientras que el modo usuario restringe las operaciones para evitar que el código no autorizado acceda a recursos críticos del sistema.

2.2 Tipos de interrupciones

TipoOrigenEjemploModo de operación
Interrupciones de hardware Generadas por dispositivos externos, como teclados, discos duros o tarjetas de red, para notificar eventos al procesador. Una tecla presionada en el teclado genera una señal que indica al sistema operativo que debe procesar esta entrada. Al ocurrir una interrupción de hardware, el procesador cambia del modo usuario al modo kernel, permitiendo al sistema operativo manejar la solicitud de manera segura.
Interrupciones de software Generadas por programas en ejecución para solicitar servicios al sistema operativo (como lectura/escritura en disco). Un programa que realiza una llamada al sistema (como open() para abrir un archivo) genera una interrupción de software. Estas interrupciones también hacen que el procesador pase del modo usuario al modo kernel, permitiendo al sistema operativo gestionar la solicitud del proceso.
Trampas (traps) Generadas internamente por el procesador, típicamente como respuesta a condiciones excepcionales o errores en tiempo de ejecución. Una operación de división por cero o una instrucción no válida genera una trampa. Las trampas fuerzan un cambio al modo kernel, donde el sistema operativo puede manejar la situación, ya sea terminando el programa, informando un error o tomando medidas de recuperación.

2.3 Llamadas al sistema

En la sección anterior, exploramos cómo el sistema operativo puede definirse tanto por sus funciones como por su ubicación en el espacio del kernel, que es el lugar donde se ejecuta el núcleo y otros componentes esenciales. También analizamos la diferenciación entre el modo kernel y el modo usuario, y cómo estos modos están vinculados a la arquitectura del procesador para garantizar la seguridad y estabilidad del sistema.

En este contexto, las aplicaciones o procesos —que son programas en ejecución— se ejecutan en el espacio de usuario. Debido a las restricciones inherentes a este modo, los procesos no pueden acceder directamente al hardware ni a recursos privilegiados, como la memoria o los dispositivos de entrada/salida. En su lugar, cuando necesitan realizar estas operaciones, recurren a llamadas al sistema para solicitar al sistema operativo que actúe como intermediario. Estas solicitudes generan un cambio del modo usuario al modo kernel, lo que permite al sistema operativo manejar las operaciones críticas de manera segura.

3. Proceso de arranque

El arranque de un sistema operativo sigue una secuencia precisa que inicia con la carga y ejecución del firmware de la placa madre (BIOS o EFI) y finaliza con la inicialización del núcleo del sistema operativo. Esta secuencia depende de elementos clave como el esquema de particiones (MBR o GPT) y el tipo de firmware, los cuales interactúan para localizar y cargar el sistema operativo.

3.1.1 Encender el sistema

  • Al encender la computadora, el procesador carga en la RAM el firmware de la placa madre desde la memoria ROM, EEPROM o Flash donde está almacenado.
  • El firmware es un software básico que inicializa el hardware y gestiona los primeros pasos del proceso de arranque.

3.1.2 Verificar el hardware (POST)

  • El firmware ejecuta el Power-On Self Test (POST), un proceso que comprueba el estado y funcionamiento básico de los componentes, como la memoria RAM, la CPU, la tarjeta gráfica y los dispositivos de entrada/salida.
  • Si POST detecta errores críticos, el arranque se detiene y el sistema puede emitir códigos sonoros (beeps) o mostrar mensajes en pantalla.

3.1.3 Seleccionar el dispositivo de arranque

  • El firmware consulta la configuración del orden de arranque, almacenada en la CMOS RAM, una pequeña memoria alimentada por una batería en la placa madre.
  • Según el orden configurado (por ejemplo, disco duro, unidad USB, red), el firmware selecciona el dispositivo donde buscará el sistema operativo.

3.1.4 Determinar el esquema de particiones

El firmware utiliza el esquema de particiones del dispositivo de arranque (MBR o GPT) para interpretar cómo está organizado el disco y localizar el cargador de arranque.

Por qué el firmware necesita un esquema de particiones: el firmware no "sabe" de antemano cómo está estructurado el disco; necesita un estándar como MBR o GPT para identificar las particiones disponibles, ubicar el código de arranque necesario (que puede estar en el sector de arranque -MBR- o en una partición especial -ESP en GPT-), y determinar cómo acceder a los datos siguiendo las reglas definidas por el esquema de particiones. Sin esta información, el firmware no podría localizar ni cargar el cargador de arranque ni el sistema operativo.

Si el sistema utiliza BIOS

BIOS busca el Master Boot Record (MBR) en el primer sector del disco (sector 0). Este contiene una tabla de particiones que describe las particiones primarias del disco, un bloque de código de arranque que inicia el cargador del sistema operativo, y una marca de arranque (el valor 55AAh en los dos últimos bytes del sector, indicando que el disco es arrancable). Si el MBR está presente y válido, el código de arranque se carga en la RAM y el control se transfiere a este código.

Si el sistema utiliza EFI

EFI (o UEFI) es un firmware más avanzado que busca la EFI System Partition (ESP), definida en el esquema GPT. La ESP es una partición especial donde se almacenan los cargadores de arranque y aplicaciones de arranque, utiliza el sistema de archivos FAT32 (compatible con una amplia variedad de hardware) y contiene archivos como bootx64.efi, que cargan el sistema operativo. EFI utiliza la información de GPT para localizar la ESP, cargar el cargador de arranque en la RAM y transferir el control.

3.1.5 Cargar el manejador de arranque

  • Una vez identificado, el manejador de arranque (como GRUB o Windows Boot Manager) toma el control del arranque.
  • Presenta un menú (si hay múltiples sistemas operativos) y localiza el núcleo del sistema operativo en el sistema de archivos, cargándolo en la memoria RAM.

3.1.6 Iniciar el núcleo del sistema operativo

El núcleo del sistema operativo se descomprime y comienza la inicialización del hardware.

En LinuxEn Windows
Se carga el initramfs (sistema de archivos inicial). Se monta el sistema de archivos raíz. Se ejecuta el proceso inicial (init o systemd) para iniciar servicios del usuario. Se carga el núcleo (ntoskrnl.exe), que inicializa los controladores esenciales y servicios básicos. Se activa el registro y se inicializa el entorno gráfico.

3.1.7 Transición al entorno del usuario

Una vez cargados los servicios y el núcleo operativo, el sistema está listo para recibir entradas del usuario a través de la interfaz gráfica o la consola.

3.2 Resumen del proceso

  1. El firmware (BIOS/EFI) se carga en la RAM y inicializa el hardware.
  2. Se selecciona el dispositivo de arranque según el orden definido en la CMOS.
  3. BIOS busca el MBR (con marca 55AAh); EFI busca la ESP.
  4. Se carga el manejador de arranque en la RAM.
  5. El manejador carga el núcleo del sistema operativo.
  6. El núcleo inicializa el hardware y los servicios.
  7. Se transfiere el control al entorno del usuario.

Esta secuencia asegura que el sistema operativo pueda iniciarse correctamente, con cada componente cumpliendo un rol esencial en el proceso.

4. Gestión de Entrada/Salida y de Memoria

4.1 Gestión de Entrada/Salida

La gestión de memoria en los sistemas operativos no solo se ocupa de optimizar el uso de la RAM, sino también de la correcta comunicación entre el software y el hardware a través de los dispositivos de Entrada/Salida (E/S). La jerarquía de E/S, tal como la describe Tanenbaum, establece una estructura que organiza el flujo de datos entre los procesos de usuario y los dispositivos físicos, al mismo tiempo que asegura la protección de la memoria y los recursos del sistema.

4.1.1 Jerarquía de Entrada/Salida

La jerarquía de E/S es un modelo que describe cómo el sistema operativo maneja las operaciones de entrada y salida a través de diferentes capas. Estas capas incluyen el hardware físico, los controladores, el sistema de archivos, y las bibliotecas de E/S, hasta llegar a las aplicaciones de usuario que realizan las operaciones finales.

CapaFunción
HardwareDispositivos físicos (discos, teclados, pantallas, etc.), conectados al sistema operativo mediante controladores y manejadores de interrupciones.
Manejadores de InterrupcionesParte del sistema operativo que gestiona las interrupciones generadas por el hardware (teclas pulsadas, paquetes de red, fin de operación de disco). Diseñados para ser rápidos y eficientes.
Controladores de Dispositivos (Drivers)Programas de software que traducen las solicitudes de E/S de alto nivel del sistema operativo o las aplicaciones en instrucciones específicas que el hardware puede ejecutar. No confundir con la controladora de disco, que es el componente físico que gestiona la transferencia de datos.
Sistema de E/S GenéricoAbstrae los detalles de los controladores y gestiona la cola de solicitudes de E/S, el buffering y el caching, optimizando el acceso a los dispositivos.
Sistema de ArchivosOrganiza y gestiona los datos en los dispositivos de almacenamiento, proporcionando una interfaz para manipular archivos y directorios de manera independiente del hardware.
Bibliotecas de Entrada/SalidaSoftware independiente del sistema operativo que ofrece funciones estándar de E/S (como fopen(), fclose() o printf() en C), sin que el programador deba ocuparse de los detalles del hardware.
Aplicaciones de UsuarioRealizan operaciones de E/S utilizando las bibliotecas de entrada/salida, sin interactuar directamente con el hardware.

4.1.2 Anillos de Protección y Gestión de Recursos Críticos

¿Los controladores de dispositivos deben ejecutarse en modo kernel o en modo usuario?

La ejecución de controladores de dispositivos plantea una cuestión importante sobre el nivel de privilegios más adecuado para garantizar tanto su funcionalidad como la seguridad del sistema. Además de los modos kernel y usuario, los procesadores modernos cuentan con un sistema de anillos de protección. Estos anillos organizan los niveles de privilegio en el acceso a los recursos del sistema, desde el Anillo 0 (modo kernel), que tiene acceso total al hardware y todos los recursos críticos, hasta el Anillo 3 (modo usuario), donde los procesos tienen privilegios limitados para prevenir posibles daños al sistema.

Los controladores de dispositivos necesitan privilegios suficientes para interactuar directamente con el hardware, lo que normalmente justificaría su ejecución en el Anillo 0. Sin embargo, otorgarles acceso total al sistema puede ser un riesgo, ya que podrían acceder a memoria o recursos críticos no relacionados con su tarea. Por esta razón, lo más adecuado sería que los controladores de dispositivos se ejecuten en un anillo de protección intermedio, que les permita comunicarse eficazmente con el hardware sin comprometer la seguridad del sistema al restringir su acceso a memoria y recursos ajenos a su función específica.

4.2 Gestión de Memoria

4.2.1 Problemas de Protección y Reubicación en la Gestión de Memoria

La protección y la reubicación son dos problemas fundamentales que un sistema operativo debe resolver al gestionar la memoria de un sistema. Ambos problemas están intrínsecamente relacionados con la capacidad del procesador para traducir las direcciones virtuales (o lógicas) generadas por un programa en direcciones reales (o físicas) en la memoria principal.

4.2.1.1 Protección: implica garantizar que un proceso no pueda acceder al espacio de memoria de otro proceso ni a las áreas reservadas para el sistema operativo. Esto es fundamental para evitar conflictos, corrupción de datos o comportamientos inesperados entre procesos.

4.2.1.2 Reubicación: implica que el sistema operativo debe ser capaz de asignar un proceso a cualquier área libre de la memoria física en el momento de su ejecución. Esto permite aprovechar la memoria disponible de manera eficiente, ya que los procesos no dependen de estar ubicados en un lugar específico.

Traducción de Direcciones Virtuales a Reales: resolver estos problemas requiere que el procesador traduzca las direcciones virtuales generadas por las instrucciones de código máquina del programa en direcciones reales en la memoria física. Esta traducción es posible gracias a mecanismos específicos del procesador, que trabajan con información proporcionada por el sistema operativo. Los métodos más comunes para realizar esta traducción son el uso de registros base y límite (en el caso del intercambio) o tablas de páginas (en el caso de la paginación).

4.2.2 Intercambio (Swapping)

El intercambio (swapping) es un método básico para gestionar la memoria y resolver los problemas de protección y reubicación. Este mecanismo mueve procesos completos entre la memoria principal (RAM) y el almacenamiento secundario (como discos duros o SSD) para liberar espacio y permitir la multitarea.

4.2.2.1 Traducción de Dirección Virtual a Real en el Intercambio

El procesador utiliza dos registros clave:

  • Registro Base: contiene la dirección de memoria física donde comienza el proceso en la RAM.
  • Registro Límite: define el tamaño máximo de memoria asignada al proceso.

Cuando una instrucción del programa genera una dirección virtual, el procesador realiza los siguientes pasos:

  • Comprobación de Protección: la dirección virtual se compara con el valor en el registro límite. Si la dirección virtual es mayor que el límite, el procesador genera una excepción, evitando accesos no autorizados.
  • Traducción: si la dirección virtual es válida, se suma al valor del registro base para obtener la dirección física real.

4.2.2.2 Protección en el Intercambio

Los registros base y límite garantizan que el proceso solo pueda acceder a su espacio asignado. Si un proceso intenta acceder a una dirección fuera de su rango, el procesador bloquea el acceso y genera una interrupción.

4.2.2.3 Limitaciones del Intercambio

  • El intercambio requiere mover procesos completos entre RAM y almacenamiento secundario, lo que puede ser lento y consume recursos.
  • Es ineficiente para manejar procesos grandes o un gran número de procesos.

4.2.3 Paginación

La paginación es un método más avanzado que divide tanto la memoria virtual como la memoria física en bloques de tamaño fijo llamados páginas y marcos, respectivamente. Este método resuelve los problemas de protección y reubicación de manera más eficiente y flexible que el intercambio.

4.2.3.1 Traducción de Dirección Virtual a Real en la Paginación

El procesador utiliza una estructura llamada tabla de páginas, que mapea las páginas virtuales del proceso a los marcos físicos en la RAM.

  • Estructura de la dirección virtual: se divide en dos partes — el número de página (identifica la página en el espacio virtual del proceso) y el desplazamiento dentro de la página (especifica la ubicación exacta dentro de esa página).
  • Proceso de traducción: el procesador consulta la tabla de páginas del proceso, almacenada en memoria; utiliza el número de página para encontrar el marco correspondiente en la memoria física; y combina la dirección base del marco con el desplazamiento dentro de la página para obtener la dirección física real.
  • Comprobación de protección: cada entrada en la tabla de páginas incluye permisos (lectura, escritura, ejecución) que el procesador verifica antes de acceder a una dirección. Si el proceso intenta acceder a una página para la que no tiene permisos, el procesador genera una excepción.

4.2.3.2 Ventajas de la Paginación sobre el Intercambio

  • Flexibilidad en la ubicación de los procesos: en el intercambio, un proceso debe ocupar un bloque contiguo de memoria física, lo que puede fragmentar la memoria. En la paginación, las páginas de un proceso pueden distribuirse en diferentes marcos de la memoria física, eliminando la necesidad de bloques contiguos.
  • Mejor uso de la memoria: la paginación permite cargar solo las páginas necesarias de un proceso, mientras que el intercambio requiere cargar el proceso completo. Esto optimiza el uso de la RAM y permite que más procesos se ejecuten simultáneamente.
  • Eficiencia en la gestión de memoria virtual: la paginación admite memoria virtual, donde el espacio de direcciones virtuales es mayor que la RAM disponible, gracias a la carga y descarga dinámica de páginas.

4.2.4 Conclusión

Tanto el intercambio como la paginación resuelven los problemas de protección y reubicación al permitir que los procesos se alojen en cualquier lugar de la memoria y evitar accesos no autorizados. Sin embargo, la paginación es una solución superior porque reduce la fragmentación, optimiza el uso de la memoria física y facilita la ejecución simultánea de múltiples procesos con menos requisitos de espacio en la RAM. Esto la convierte en el estándar para la gestión de memoria en los sistemas modernos.

5. Gestión de Procesos

La gestión de procesos es una de las funciones más importantes de un sistema operativo. Consiste en administrar los recursos y las tareas asociadas a los programas en ejecución (procesos) para garantizar que se utilicen de manera eficiente, permitiendo la multitarea, la comunicación entre procesos y la estabilidad del sistema.

5.1.1 Procesos e Hilos

Proceso

Un proceso es una instancia de un programa en ejecución. Cada proceso tiene su propio espacio de memoria (direcciones de memoria independientes) y recursos, como archivos abiertos y dispositivos. Es una unidad de aislamiento; los procesos no comparten directamente su memoria con otros procesos.

Hilo

Un hilo es la unidad más pequeña de ejecución dentro de un proceso. Todos los hilos de un proceso comparten su espacio de memoria y recursos asociados. Cada hilo tiene su propia pila, contador de programa y registros.

El sistema operativo utiliza una estructura llamada tabla de procesos para mantener información sobre cada proceso. Esta tabla incluye:

5.1.2 Planificación de Procesos

La planificación de procesos es el mecanismo mediante el cual el sistema operativo gestiona el cambio de estado de los procesos y decide qué proceso debe ejecutarse en cada momento. Este proceso asegura un uso eficiente de la CPU, la equidad entre los procesos y la capacidad de multitarea.

Los procesos pueden pasar entre tres estados principales:

  • Listo: el proceso está preparado para ejecutarse pero espera su turno.
  • En ejecución: el proceso está utilizando la CPU y ejecutando sus instrucciones.
  • Bloqueado: el proceso está esperando un evento externo (como una operación de entrada/salida).

El planificador de procesos es responsable de mover los procesos entre estos estados, dependiendo de las condiciones del sistema. Utiliza estructuras como colas para gestionar los procesos en los diferentes estados.

5.1.2.1 De "Listo" a "En ejecución"

Cuando un proceso pasa de estar listo a en ejecución, el planificador selecciona el siguiente proceso de la cola de procesos listos y asigna la CPU a ese proceso.

Interrupción de reloj en este contexto: el sistema operativo configura un temporizador de reloj para garantizar que el proceso no monopolice la CPU. Cuando el temporizador expira, se genera una interrupción de reloj, y el sistema operativo toma el control: guarda el estado del proceso actual (registros, contador de programa, etc.) en su tabla de procesos (cambio de contexto), devuelve el proceso actual a la cola de listos, selecciona un nuevo proceso de la cola de listos y restaura su estado, y el nuevo proceso comienza su ejecución.

5.1.2.2 De "En ejecución" a "Bloqueado"

Un proceso pasa del estado en ejecución a bloqueado cuando necesita esperar un evento externo, como la finalización de una operación de entrada/salida o la disponibilidad de un recurso.

Cómo ocurre esto: el proceso realiza una llamada al sistema (por ejemplo, para leer un archivo); el sistema operativo lo pone en la cola de procesos bloqueados; el planificador selecciona otro proceso listo para ocupar la CPU.

Ejemplo: un programa solicita leer datos de un disco. Mientras la operación de lectura se completa, el proceso se bloquea, liberando la CPU para otros procesos.

5.1.2.3 De "Bloqueado" a "Listo"

Un proceso bloqueado pasa a listo cuando el evento externo que esperaba ocurre, como la finalización de una operación de entrada/salida.

Cómo ocurre esto: el controlador de hardware genera una interrupción para notificar al sistema operativo que el evento ha terminado (por ejemplo, la lectura de un archivo está completa); el sistema operativo mueve el proceso desde la cola de bloqueados a la cola de listos.

Ejemplo: un proceso que estaba esperando la entrada de un usuario mediante teclado se desbloquea cuando el usuario escribe los datos, y queda listo para volver a ejecutarse.

5.1.3 Conclusión

La gestión de procesos por parte del sistema operativo incluye la creación, ejecución, suspensión y terminación de procesos, garantizando el uso eficiente de los recursos. Los procesos son unidades aisladas, mientras que los hilos permiten concurrencia dentro de un mismo proceso. La planificación de procesos, junto con el uso de interrupciones de reloj, asegura que todos los procesos reciban tiempo de CPU, manteniendo la estabilidad y el rendimiento del sistema.
